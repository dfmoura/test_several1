----------------------------------------------------------------------------------------------------
A.2. Rede mínima (sem NAT Gateway)
----------------------------------------------------------------------------------------------------

  1. Use a VPC default OU crie VPC simples com 1 subnet pública.
  2. NÃO crie NAT Gateway (custo fixo ~USD 68/mês desnecessário neste porte).
  3. Security Group `sg-erp-rlp`:
       INBOUND:
         443/tcp  ← 0.0.0.0/0   (HTTPS)
         80/tcp   ← 0.0.0.0/0   (redirect → 443; depois pode fechar)
         22/tcp   ← NADA (fechado)
       OUTBOUND: all (Focus, banco, Meta, apt, ECR…)
  4. Elastic IP — alocar e associar à EC2 depois.

  CHECKPOINT:
    [ ] SG sem porta 22 aberta
    [ ] Sem NAT Gateway na fatura

D.2. Integrações free JÁ NO FORMULÁRIO (backend proxy — não chamar do browser)
----------------------------------------------------------------------------------------------------

  Princípio (APIS_FREE):
    Evento humano → API backend → cache api_cache → preenche formulário →
    usuário CONFIRMA → grava snapshot (fonte, data, resumo).

  Endpoints internos:

    GET /api/v1/consultas/cnpj/{cnpj}
        → BrasilAPI /api/cnpj/v1/{cnpj}
        → valida dígito ANTES de chamar
        → cache 30 dias (situação cadastral); TTL menor se quiser

    GET /api/v1/consultas/cep/{cep}
        → ViaCEP ou BrasilAPI CEP v2
        → devolve logradouro, bairro, município, uf, ibge
        → cache 90 dias

    GET /api/v1/consultas/ncm?q=
        → busca LOCAL na tabela ncm (carga Siscomex/BrasilAPI)
        → autocomplete; API externa só no job de atualização mensal

    GET /api/v1/consultas/bancos
        → BrasilAPI /banks/v1 (cache longo) p/ dados bancários do parceiro

    GET /api/v1/municipios?uf=MG
        → tabela local IBGE

  UX do formulário de parceiro (resultado que o usuário “vê”):

    1. Digita CNPJ → blur/botão “Consultar CNPJ”
    2. Spinner curto (<2s típico) OU mensagem “usando cache de DD/MM”
    3. Campos preenchidos: razão social, fantasia, CNAE, endereço sede, CEP, UF
    4. Badge discreto: “Sugestão BrasilAPI · confirmar antes de salvar”
    5. Digita CEP → preenche logradouro/bairro/município/IBGE; usuário só completa nº
    6. Salvar → PAR-00xx criado; audit_log + snapshot da consulta

  Cadência / proteção (APIS_FREE):
    [ ] Rate limit por user (ex.: 30 CNPJ/hora)
    [ ] Circuit breaker se BrasilAPI 429/5xx → mensagem amigável + retry manual
    [ ] Nunca job noturno varrendo milhares de CNPJ
    [ ] Fallback OpenCNPJ/ReceitaWS só se BrasilAPI falhar (e respeitando limites)

    Editor de ORC: cabeçalho + itens + cenários + gordura + imposto ESTIMADO
    Botão “Enviar link de aceite” → e-mail/WhatsApp oficial (e-mail primeiro)

  Regras:
    - Prospect pode orçar; PED exige cadastro completo (ORCAMENTO_PROSPECT…)
    - Imposto no ORC = simulação (VERIFICACAO_IMPOSTO_ORCAMENTO) — não é NF
    - Versão/cenário travados no aceite
    - Alçada de gordura (GORDURA_ORCAMENTO…); FLEXIBILIDADE_LIMITES…

----------------------------------------------------------------------------------------------------
E.2. Aceite por LINK (nunca “combinado no zap”)
----------------------------------------------------------------------------------------------------

  Rota pública assinada:
    GET  /aceitacao/{token}     → página somente leitura do ORC
    POST /aceitacao/{token}     → aceita / recusa

  Resultado do aceite:
    - Cria PED-… com SNAPSHOT de itens/preços (não recalcula)
    - ORC → CONVERTIDO
    - Evento PedidoCriado (outbox)

----------------------------------------------------------------------------------------------------
E.3. Crédito (CRT) — escrita no Financeiro, consulta no Comercial
----------------------------------------------------------------------------------------------------

  Telas FINANCEIRO:
    Limite do cliente; liberação manual; adiantamento (BX parcial)

  Regra: produção só após CRT OK ou BX de sinal (DECISAO §5.3).
  Status PED: RASCUNHO_COMERCIAL → AGUARDANDO_CREDITO → LIBERADO → …

  CHECKPOINT — O QUE VOCÊ DEVE VER (demo de 10 minutos):
    [ ] COMERCIAL cria ORC-0001 com 2 itens PRODUCAO + 1 REV
    [ ] Imposto estimado aparece; total com gordura dentro da alçada
    [ ] Envia link → Mailpit mostra e-mail
    [ ] Cliente aceita no link → PED-0001 nasce com mesmos preços
    [ ] FINANCEIRO libera crédito → PED LIBERADO
    [ ] COMERCIAL tenta alterar preço do PED → bloqueado (snapshot)

F.2. OP / OS a partir do item do PED
----------------------------------------------------------------------------------------------------

F.3. Conclusão
----------------------------------------------------------------------------------------------------

  Conclusão OP: entra PA no estoque; libera política de faturamento do item.
  Conclusão OS: marca serviço pronto a faturar.

  CHECKPOINT — O QUE VOCÊ DEVE VER:

  # --- Local (notebook) ---
  git clone <repo-erp-rlp> && cd erp-rlp
  cp .env.example .env

  cd /opt/erp-rlp
  git pull   # ou docker pull ghcr.io/.../api:$SHA
  export $(sudo aws ssm get-parameters-by-path --path /rlp/prod --with-decryption \
           --query 'Parameters[*].[Name,Value]' --output text | sed 's#/rlp/prod/##')
  docker compose -f docker-compose.yml -f docker-compose.prod.yml pull
  docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d
  docker compose exec app php artisan migrate --force
  docker compose exec app php artisan config:cache
  curl -fsS https://erp.rlpetiquetas.com.br/api/v1/health
