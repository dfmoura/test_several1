----------------------------------------------------------------------------------------------------
1.1. O PROBLEMA NÃO É A AWS — É O MODELO COPIADO DE EMPRESA GRANDE
----------------------------------------------------------------------------------------------------

  Padrão “enterprise” que inchou o orçamento:

                    Internet
                       │
                      ALB  ←── custo fixo ~USD 28–42/mês
                       │
              ┌────────┴────────┐
              │  subnet privada │
              │  Fargate API    │
              │  Fargate worker │
              └────────┬────────┘
                       │
                  NAT Gateway  ←── vilão #1 em sa-east-1 (~USD 68/mês parado)
                       │
                 Focus / banco / Meta

  Com 200 NF/mês o tráfego de dados é BAIXO. Você paga a TARIFA HORÁRIA
  desses componentes, não o processamento das notas.

  Distribuição típica do “Cenário B legado” (errado como padrão RLP):

    NAT Gateway ...................... 20 – 30%   ← quase fixo, tráfego irrelevante
    RDS .............................. 25 – 35%   ← quase fixo 24×7
    ALB .............................. 10 – 15%   ← quase fixo
    Fargate (API+worker) ............. 12 – 20%
    Segurança + logs ................. 8 – 15%
    S3 + SQS + SSM + SES ............. < 8%   ← o que realmente escala com NF

  Insight: com o volume da RLP, ~60–75% da fatura é POSTO FIXO de rede/entrada/
  banco ligado — não “custo por nota”. Cortar NF não baixa a conta; cortar NAT/ALB
  e consolidar compute sim.

4. CENÁRIO E — MÍNIMO VIÁVEL (USD 55–120) — PILOTO / BUDGET APERTO
====================================================================================================

Objetivo: menor conta possível ainda profissional o bastante para emitir NF
e cobrar com segurança de negócio.

  Opção E1 — Amazon Lightsail (simples de operar):
    1 instância 2–4 GB RAM + disco + IP estático + snapshot
    App + Postgres no mesmo host (Docker Compose)
    Bucket S3 à parte para XML/PDF (ou disco + sync)
    Faixa típica: USD 20 – 60 compute + 10 – 30 extras = USD 55 – 100

  Opção E2 — 1× EC2 t4g.small “tudo junto”:
    API + worker + Postgres + Caddy
    Backup: pg_dump agendado → S3 + snapshot EBS semanal
    Faixa típica: USD 55 – 120

  Aceitar conscientemente:
    • Banco e app no mesmo host (incidente de host afeta os dois)
    • Sem autoscaling (com 10 users não precisa)
    • Menos “carinhas” AWS na fatura — mais disciplina operacional no host

  NÃO aceitar:
    • Sem backup / sem restore testado
    • Sem HTTPS
    • Sem kill-switch de integração
    • Root AWS no dia a dia

12. DECISÕES INTELIGENTES (FUNCIONAR + CABER NO BOLSO)
====================================================================================================

  1. PORTE MANDA NO DESENHO
     10 users / 200 NF → 1 VM (ou Lightsail), não cluster. Ponto.

  2. NAT GATEWAY É SUSPEITO Nº 1 EM sa-east-1
     ~USD 68/mês parado. Só mantenha com requisito escrito de subnet privada.

  3. ALB NÃO É SINÔNIMO DE SEGURANÇA
     HTTPS + SG + rate limit + SSM já atendem ERP interno neste porte.

  4. CONSOLIDAR COMPUTE
     API + worker no mesmo host. Separar só com evidência (CPU/fila).

  5. BANCO: MICRO OU NO HOST NO DIA 1
     Subir sizing só com CPU/memória > 70% sustentado ou restore exigindo RDS.

  6. FILA BARATA (SQS) > Redis pago
     Idempotência no Postgres.

  7. NONPROD DORME
     Staging sob demanda. Dev local em Docker Compose.

  8. LOG COM DIETA
     Sem payload completo de webhook; retenção 7–14d.

  9. ANTI-LOOP É FINOPS
     200 NF viram 20.000 se job enlouquecer — teto + DLQ + kill-switch.

 10. MEDIR 30 DIAS ANTES DE RI/SAVINGS/MULTI-AZ
     Rightsizing primeiro; compromisso longo depois.

 11. NÃO COMPRAR HA “POR MEDO”
     Snapshot + restore ensaiado + runbook costam menos que Multi-AZ no dia 1.

 12. REVISAR FATURA NO DIA 7, 30 E 90
     Qualquer linha > 15% sem justificativa de volume = investigação.
