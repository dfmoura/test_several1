1. OBJETIVO
--------------------------------------------------------------------------------
Validar, no padrão profissional desta instalação, se o “clique”
(resposta perceptível após ação do operador) permanece aceitável
com até 5 usuários simultâneos nesta configuração Lightsail / Compose.

O teste NÃO propõe otimização, php-fpm, Redis, RDS nem revisão geral.
O teste CONFIRMA o envelope e fecha a política de uso.


--------------------------------------------------------------------------------
2. DEFINIÇÕES (para não misturar métricas)
--------------------------------------------------------------------------------
A) Usuário cadastrado
   Conta no banco. Não consome o “atendente” PHP enquanto não clica.

B) Usuário logado (sessão)
   Token/sessão válida (SESSION_DRIVER=database, lifetime 120 min).
   Barato. Aba aberta sem clicar quase não pesa.

C) Usuário simultâneo (escopo deste teste) ★
   Logado E clicando (listar, abrir ficha, calcular ORC, enviar, etc.).
   Política adotada: no máximo 5.

D) Clique
   Um pedido HTTP da SPA → nginx → PHP (artisan serve) → MySQL → JSON.
   Nesta caixa: 1 processo PHP atende 1 pedido por vez (fila curta).

E) Link público da proposta (/p/{token})
   NÃO conta como um dos 5 logados, mas USA o mesmo PHP.
   Com 5 operadores, aberturas ocasionais de cliente são aceitáveis.

3. ARQUITETURA SOB TESTE (fatores do clique)
--------------------------------------------------------------------------------
Internet → :443 (TLS no host) → web:80 (nginx SPA)
                              → app:8000 (Laravel · php artisan serve)
                              → mysql (volume local, sem publish)
                              → queue (worker; hoje ocioso no FLEXORC)

Memória Compose (mem_limit):
  mysql 384m · app 192m · queue 384m · web 48m · Σ ~1,0 GB
  Host 2 GB + swap 2 GB (rede de segurança)

Gargalo do clique: CPU + fila do PHP de um processo — NÃO o disco 60 GB.
Envelope oficial herdado: ≤10 usuários; operação FLEXORC: teto 5.
